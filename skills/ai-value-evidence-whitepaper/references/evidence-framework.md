# 完整证据型框架 / Bilingual evidence-led outline

Adapt scope to the engagement; do not manufacture evidence or force an irrelevant section. The Chinese and English versions must carry equivalent substance and qualifications.

1. 执行摘要 / Executive summary — decision, solution, substantiated results, economics, limits.
2. 行业与客户需求 / Industry context and customer need — evidence-backed segment, region, buying decision, task and baseline.
3. 解决方案与架构 / Solution architecture — configuration, models, versions, data path, deployment and support boundaries.
4. 工作负载与对照方案 / Workloads and comparators — representative tasks, data, inputs/outputs, volume and quality; comparison and differences.
5. 测试方法 / Test methodology — hardware and software, scenario, sample, configuration, concurrency, repetitions, measurement and raw evidence.
6. 结果与质量 / Results and quality — quality, correct-task completion, failures/retries, TTFT and end-to-end latency, throughput, per-request versus aggregate; no unsupported extrapolation.
7. 系统容量 / Capacity — service-quality target, concurrency sweep, sustained operation, limits and variability.
8. 价值与经济性 / Business value and economics — actual cost inputs, formula, comparable work, cost per passed task, TCO, sensitivity; no fabricated ROI.
9. 落地与风险 / Implementation and limitations — integration, operations, security/data paths, applicability, test limitations, current versus planned availability.
10. 附录与披露 / Appendix and disclosure — source dates, full configurations, methodology, funding/tester/independence where relevant, customer and publication permissions.

For a gap analysis map each section to Existing / Partial / Not provided / Not applicable, current evidence, specific missing fields, proposed evidence, suggested owner role and priority. Prioritize baseline, one representative task, reproducible conditions, quality, real economics and permission over optional third-party validation. External organizations are needed only where independent third-party work or endorsement is actually desired.
