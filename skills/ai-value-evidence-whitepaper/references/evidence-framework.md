# 白皮书通用结构 / Shared bilingual whitepaper outline

围绕一个明确客户、任务和决策撰写；下列章节可根据简版/证据型裁剪，核心限制与披露必须保留。Use for either tier; scale depth to available evidence. Annotate unsupported or incomplete claims in yellow with a text label and carry IDs into the review evidence register. / 缺失或待验证处标黄并附文字，审阅稿用主张 ID 连接证据。

| 章节 / Section | 简版 / Brief | 证据型 / Evidence-led |
|---|---|---|
| 1. 作者与利益披露 / Authorship and interests | 作者、出售的产品、测试与资助方；缺项标黄 | 加入测试独立性、供应商参与和权限 |
| 2. 执行摘要 / Executive summary | 客户问题、已有结果、限制，不把假设写成事实 | 主要比较、质量、价值与限制 |
| 3. 客户、任务与现状 / Target customer and baseline | 行业、地区、用户、决策者、任务和当前流程 | 任务来源、频率、现状质量及采购驱动 |
| 4. 方案与边界 / Solution and scope | 组件、版本、数据流及可用范围 | 架构、配置、集成、运行与支持边界 |
| 5. 对照 / Comparators | 当前做法及一个现实替代方案；缺失标黄 | 适用时同时覆盖当前方式、市场及同类产品替代；披露配置差异 |
| 6. 结果与质量 / Results and quality | 有条件的实测；成功和失败并列 | 方法、样本、质量门槛、失败/重试、延迟和容量 |
| 7. 客户价值 / Value levers | 列适用维度、基线、指标和证据类型 | 生产力、质量/风险、数据控制、体验/连续性、成本和新增能力；不把新增能力直接当节省 |
| 8. 经济性 / Economics | 已知价格、成本、周期和缺口 | 同口径总成本、合格任务成本、双向盈亏条件及敏感性 |
| 9. 混合运行 / Hybrid operation | 仅适用时：本地/外部路由与边界 | 路由比例、升级原因、每任务外部费用及质量对照 |
| 10. 何时不合适 / When not to choose | 根据真实限制说明不适合场景；依据不足标黄 | 列失败任务、替代方案优势及适用条件 |
| 11. 完整产品与部署 / Whole product and deployment | 已交付、任务必要组件、支持与缺口 | 另列集成、伙伴、管理、培训、维护及未来计划；规划不写成现有能力 |
| 12. 来源与方法 / Sources and methods | 逐主张 ID、来源、日期、权限和条件 | 完整配置、测试主体、原始记录、方法及限制 |
| 13. 市场证据 / Market evidence | 如有授权可公开的客户、合作伙伴或第三方证据 | 写明取得的支持和覆盖范围；缺失即缺失，不暗示背书 |

审阅稿为 `DRAFT — NOT FOR DISTRIBUTION / 审阅稿 · 请勿对外分发`。正式发布需负责人完成事实、权限与标黄处理及人工审阅；脚本不能自动判定已具备公开条件。 / Label review drafts; human review decides release.
