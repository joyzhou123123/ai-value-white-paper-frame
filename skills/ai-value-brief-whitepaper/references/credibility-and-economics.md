# 评估、价值和公信力 / Credibility, value and evaluation

## 基本规则 / Principles
- 开头披露作者、产品利益、测试方及资助；客户问题先于产品宣传。按证据如实保留成功与失败，并写何时不适用。
- 测试前记录任务来源、基线、评分标准和通过阈值；事后修改说明原因。参考答案也须核验，不能默认任一厂商为真值。
- 对照应覆盖当前做法及现实替代，适用时另列市场替代与同类产品；按对方推荐配置或解释差异。不要求虚构“竞品胜出”，应披露实际弱项或“未观察/未测试”。
- 每项主张分开记录完成状态 `status` 与证据类型 `grade`：`measured` 实测、`calculated` 计算、`third_party` 第三方、`vendor_stated` 厂商说明、`hypothesis` 假设、`illustrative` 示例。另记 `source_role`（作者、供应商、独立机构等），区分来源身份与证据类型；竞品厂商数据不能因此当成独立测评。
- 每个价值维度记录基线、指标、结果、质量、证据类型及边界；对生产力纳入复核，对数据控制记录真实数据路径，对新增能力不自动记为节省。
- 审阅稿与正文用 `[C-001]` 等 ID 对应证据。对外版在核验并确认发布许可后，可按选定引用规范转换为来源引用；不能把内部、客户或受限材料发布。

## 经济性 / Economics
允许当前人工、订阅、API、本地、其他设备和混合方案等多个现实选项；选项使用同一币种、地区、周期、任务及质量标准。逐项列硬件（必要时为相对原设备增量）、软件、集成、运维、电力、外部调用、审核与重试；明确哪些已包含在年成本中，避免重复计算。使用实际设备生命周期与价格日期；缺失不能当零。成本/合格任务 = 核算期总成本 ÷ 同期合格任务数。披露比较双方何时更经济；对任务量、利用率、价格、token 增长及质量做敏感性分析。示例和假设标黄，切勿当作实测 ROI。

## 设备与混合 / Devices and hybrid (when applicable)
对设备测试记录模型/来源/量化、运行时/版本、实际加速器、驱动及固件、内存配置、供电/功耗模式、上下文、I/O、并发、冷启动、持续时长、背景负载、重复次数和分布。测试前核实组件已经启用并实际参与。只有实际相关时纳入混合模块：本地合格任务占比、升级比例和原因、外部费用、检查拦截及并发饱和点。随机抽样双路盲评可减少任务分配偏差；比例按任务量和统计目标制定，5% 不是通用充分样本。模型、量化、运行时及测试日期随结果披露；发布前核对相关模型变化，必要时重测或说明结果时效。

## 审阅与发布 / Review and publication
审阅稿加 `DRAFT — NOT FOR DISTRIBUTION / 审阅稿 · 请勿对外分发`。经授权的审阅人检查：不利结果、对照是否公平、每项主张/证据类型、成本可复算、作者及利益、公开权限、事实与黄色缺口。存在未解决的关键事实、权限或黄色标记时不得视为正式对外稿；按用户要求提供审阅稿与具体缺口。真实授权和视觉黄底须人工核实，不由脚本宣称通过。
